# AdventureConnect — Visual Product Contract

## Brand promise

**Decide better. Travel better.**

The interface must make the traveler feel that AdventureConnect understands their intent before asking them to browse a catalog.

## Experience hierarchy

1. **Intent** — what kind of trip is desired.
2. **Confidence** — why a recommendation fits.
3. **Action** — plan, save, explore, or continue.
4. **Depth** — itinerary, budget, experiences, providers, sources.

## Visual language

- Cinematic photography used selectively for discovery.
- Editorial typography and strong hierarchy for trust.
- Quiet surfaces around data-heavy decisions.
- Accent color reserved for interaction and selected states.
- No generic travel-template grid as the primary product identity.
- Recommendation cards must expose score, reason, trade-offs, and next action.
- Source/provenance labels remain visible where factual confidence matters.

## Core screens

### Home
Hero intent capture → featured intelligent recommendations → destinations/experiences → guides → trust/provenance.

### Planner
Structured intent form → constraints → recommendation results → compare → build trip.

### Recommendation result
Ranked candidates with score breakdown, explanation, budget, duration, pace, and alternatives.

### Destination
Editorial introduction → fit assessment → season/cost → experiences → stay/transport → itinerary → planner CTA.

### Trip workspace
Saved destination → itinerary timeline → budget → reservations/referrals → notes.

## Responsive rule

Mobile is a first-class planning surface, not a collapsed desktop layout. Every critical action must be usable with touch and keyboard.

## Performance rule

Visual richness must never defeat the product's decision loop. Prefer responsive modern images, lazy loading below the fold, stable dimensions, and minimal client JavaScript for static content.
